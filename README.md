# 牛客岗位匹配看板

## 打开与投递

- 双击单文件离线看板可查看交付时的快照。网页版使用 `jobs.json`，刷新页面即可读取发布后的数据。
- 投递清单默认显示分数 ≥70 的岗位。可取消勾选查看本批全部岗位，再按企业、城市、分数和投递状态筛选或排序。
- 「一键投递」直接打开对应的牛客岗位入口。请在日常使用且已手动登录牛客的浏览器打开看板，在岗位页点「立即申请」，选用卡片标注的版本后手动提交。第三方招聘系统可能要求再次登录或上传简历。
- 牛客的已登录申请表和简历选择机制仍待联调。当前由本人选简历并提交。看板按牛客职位 ID 将状态存入当前浏览器，本批标记为「已投递」或「跳过」的卡片停用投递链接。浏览器、设备与页面来源变更时，投递记录分别保存。牛客确认结果后请手动更新。
- 若目标表单受牛客官方客户端支持，可使用 [NowClaw](https://www.nowcoder.com/my/resume-plugin-intro?channel=wb&tab=nowclaw) 辅助填表，并在提交前核对简历版本。

## 简历和评分

两份指定 PDF 的经历正文相同。无岗位意向的一份标为「内容与传播版」，填写营销储干及商品专员意向的一份标为「营销储干／商品版」。按 JD 岗位方向推荐版本，两份共用同一份经提取的技能词。

提取结果涵盖中文与传媒、内容策划与采编、文案与品牌传播、公众号与视频号、拍摄剪辑、海外内容本地化、数据复盘、跨团队协作、英语沟通与 Office。分数由岗位方向偏好、加权关键词覆盖、已有技能数量与识别出的差距计算。默认显示牛客官方岗位库筛出的国央企职能岗。岗位库名单存于 soe-snapshot.json，按已知截止日过滤，官网在招状态待核对。定时脚本用该名单优先生成看板，来源不足时从既有公开招聘列表补充。定时脚本不会自行重新查询授权岗位库。匹配理由列出用上的技能，差距项仅表示两份 PDF 中缺少足够证据或需要核对。简历未写预计毕业年，可在 `profile.json` 的 `graduationYear` 填入已确认的年份。年份速筛以 JD 中「届」的表达为主。

该项目只包含概括后的技能词和公开岗位字段。简历原件、姓名、联系方式、账号会话与个人投递状态均留在本地。需要使用私有评分配置时，可通过 Actions 仓库 Secret `MATCH_PROFILE_JSON` 提供同结构 JSON。部署前请检查公开看板会呈现的匹配结果。

## 数据与运行

`sources.json` 配置实际牛客公开招聘人职位列表和已知详情 ID。脚本优先核验预设的相关岗位及来源列表近期岗位，去重并核验在招状态，目标为 40 个岗位。可按需增补牛客公开招聘人列表。每天会重新核验来源，因此连续两批可能包含相同岗位。有效来源不足时显示当批实际数量。遇访问限制、验证码或整批无有效 JD 时，运行失败并保留上一份 JSON。

使用 Node.js 22 或更新版本：

```sh
node refresh.mjs
```

如已有支持 OAuth 的 Codex CLI，可安装完整的 `nowclaw-job-search` 包，重开会话并运行 `codex mcp list` 核对连接。需要添加时执行 `codex mcp add nowcoder-skills-oauth --url https://www.nowcoder.com/agent/mcp`，在牛客页面自行登录授权，再用 Skill 查询一条公开岗位验证。每日任务走公开网页读取通道，可独立运行。

## GitHub Pages

1. 把此目录中的文件连同隐藏的 `.github/workflows/pages.yml` 推送到目标仓库的默认分支 `main`。
2. 打开仓库 **Settings → Pages → Build and deployment → Source**，选择 **GitHub Actions**。
3. 在 **Actions → 牛客岗位更新及看板部署** 运行一次 **Run workflow**。检查刷新、提交、部署三个步骤，并打开 `github-pages` 环境返回的地址。
4. 定时任务设为每天香港时间 **09:17**（UTC 01:17），更新并提交 `jobs.json`，同一次工作流部署新页面。GitHub 实际排队时间可能晚于计划触发时间。仓库策略须允许工作流写入 `main` 并部署 Pages。

[GitHub Pages 自定义工作流文档](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)
